# 性能改造计划（2026-10-16，第二轮）

三份外部评审的共同结论：**当前瓶颈不在 Q 学习的配额比例，而在候选生成质量与历史信息丢失**。
本文件记录由此产生的改造顺序与判定门槛。

## 已诊断出的三个结构问题

| # | 问题 | 证据 | 改造 |
|---|---|---|---|
| 1 | **历史精英会丢失**：`verifiedMode='latest'` 会用更差的新位置覆盖该狼旧的优秀已验证位置，α/β/δ 可能因此退化 | 代码级；`eliteAnchor` 在 F13 上单次快筛领先 1000 倍 | ①`eliteAnchor`：把历史最优钉为 α；②`verifiedMode='best'` |
| 2 | **一轮内反馈滞后**：50 次评价全部做完才刷新领导层，后面的候选生成用不到前面的信息 | `DenseSync` 早期劣于 GWO | `microBatches`：把名额切成 B 批，每批后刷新领导并**重新筛选**剩余候选 |
| 3 | **筛选完全 fitness-blind**：只看几何距离，不看任何真实适应度信息 | 低预算下所有配额/准则挤在 0.82–0.90 窄带 | ③候选生成多样化 + 按"哪种生成策略真的产生过改进"分配评价名额 |

## 第二轮要实现的核心机制（拟作为本文创新点）

**Feedback-Driven Evaluation Allocation（按生成策略分配真实评价）**

- 虚拟狼分成若干**生成策略族**：
  - `S_GWO`：标准 GWO 平均移动（现状）
  - `S_XOV`：精英交叉移动 `Y ← Y + r⊙(X_α − Y_r)`（逐维，结构不同于平均移动）
  - `S_DIV`：少数派领导方向（探索）
- 每轮 50 个评价名额**按族分配**，分配比例由 Q 学习根据"哪个族最近产生过真实改进"在线调整。
- 与现状的区别：Q 学习不再学"7:3 还是 9:1"（无信息量），而是学**"哪种候选生成方式值得花昂贵评价"**。

## 判定门槛（先小规模，达到才进正式批）

开发协议：12 函数（F1,F3–F13）× 10 种子 × 100k FE。

| 门槛 | 要求 |
|---|---|
| G1 | 在 12 函数上平均排名优于现有最好变体（`Over1000-90q3`） |
| G2 | 对 GWO 的函数级胜负 ≥ 10/12 |
| G3 | 至少 1 个函数达到 Holm 校正显著 |
| G4 | CPU 不超过现有最好变体的 2 倍 |
